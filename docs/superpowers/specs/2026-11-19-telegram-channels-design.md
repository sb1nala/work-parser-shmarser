# Источник: Telegram-каналы со стажировками — дизайн

Дата: 2026-11-19
Статус: черновик, ждёт одобрения
Основной дизайн бота: `docs/superpowers/specs/2026-11-18-vacancy-bot-design.md`

## Зачем

Часть стажировок по аналитике и ML публикуется только в Telegram-каналах. Владелец каналы не читает и попросил подобрать их самостоятельно. Бот должен читать каналы сам и присылать подходящие посты через тот же фильтр, те же кнопки и ту же склейку, что и вакансии с сайтов.

## Цели

- Читать три публичных канала: `newdirections`, `not_boring_ds_jobs`, `young_june` (выбор владельца). Список каналов хранится в `config/config.yaml`, добавить канал — одна строка.
- Разбирать посты в обычный `Posting` и прогонять через существующие фильтр, склейку и рассылку.

## Не цели

- Закрытые каналы и чтение от имени аккаунта владельца (Telethon) — отвергнуто, см. «Подходы».
- Разбор постов языковой моделью.
- Картинки и вложения, только текст.

## Анти-цели

- Реклама курсов и интенсивов приходит как вакансия.
- Бот засыпает чат старыми постами.
- Сломанная вёрстка Telegram тихо обнуляет источник. Защищает существующий контроль поломок: ошибка разбора → алерт «упал», пустая выдача долгое время → алерт «пусто».

## Подходы

1. **Открытая веб-версия `https://t.me/s/<канал>` (выбор владельца).** Обычная HTML-страница с последними ~20 постами. Более старые посты подгружаются параметром `?before=<id поста>`. Не нужны аккаунт, ключи и вход. Минус: разбор HTML, который может сломаться при смене вёрстки.
2. **Telethon от имени аккаунта владельца.** Посты приходят структурированно, но нужны ключи my.telegram.org, вход по коду и файл сессии с полным доступом к аккаунту. Для трёх публичных каналов это лишний риск. Отвергнуто.
3. Бот-администратор в каналах (невозможно для чужих каналов) и платные агрегаторы (нарушают правило «ноль платных API»). Отброшены.

## Устройство

- **Один адаптер `TelegramSource`, по экземпляру на канал.** У каждого своё имя источника `tg_<канал>`, чтобы контроль поломок, тихий первый запуск и закрытие работали по каждому каналу отдельно.
- **Окно:** посты за последние `window_days` дней (по умолчанию 14). Листаем `?before=` назад, пока не встретим пост старше окна. Лимит `max_pages`. Если лимит исчерпан до выхода за окно, выбрасываем `RuntimeError` (правило «без частичных результатов»). Посты, выпавшие из окна, закрываются как обычно, без уведомлений.
- **Разбор поста:**
  - `external_id` — номер поста, `url` — `https://t.me/<канал>/<номер>`, `published_at` — дата поста (с часовым поясом);
  - название — первая непустая строка без эмодзи по краям;
  - если в первой строке есть « / » (или « — » / « | » между двумя частями), левая часть — должность, правая — компания;
  - строка, начинающаяся с «🗺» (или «📍»), даёт город и формат: «удалённо/удалёнка/remote» → REMOTE, «гибрид» → HYBRID, «офис» → OFFICE, остальное — города;
  - всё остальное — описание. Опыт и занятость не выдумываем: `None`.
- **Компания, если её нет в посте:** `"Telegram @<канал>"`. Так посты разных каналов с одинаковым названием не склеиваются между собой по пустой компании.
- **Защита от рекламы:** у каналов нет поля «опыт», а реклама интенсивов вроде «AI Analytics Week» проходит по слову «analytics». Поэтому для Telegram-источников вводится опция канала `require_level_keyword` (по умолчанию `true`): пост проходит фильтр, только если в его названии есть слово уровня (стажёр, intern, junior…). Без такого слова отсев с причиной `no_level_keyword`. Остальные правила фильтра не меняются.
- **Ошибки:** не-2xx, страница без ожидаемой разметки постов, нечитаемая дата — один `RuntimeError` с именем канала (как у других адаптеров).
- **Склейка:** обычные правила. Один канал не склеивается сам с собой; со стажировкой с сайта банка склеивается, если совпадают компания, название и решение фильтра.

## Решения владельца

- Три канала из списка выше, остальные кандидаты (`datasciencejobs`, `analysts_jobs`) пока не подключаем.
- Способ чтения: открытая веб-версия `t.me/s`.

## Решения Claude (владелец может поправить)

- Окно 14 дней, имя источника `tg_<канал>`, компания по умолчанию `Telegram @<канал>`.
- `require_level_keyword: true` для каналов, чтобы отсечь рекламу.
- Разбор HTML — стандартной библиотекой или `selectolax`/`beautifulsoup4`, на выбор разработчика. Новая зависимость допустима, если она маленькая и без нативной сборки.

## Оставлено разработчику

- Точные селекторы разметки `t.me/s`; реальная урезанная фикстура страницы в тестах.
- Набор разделителей «должность / компания» и список эмодзи для строки города.
- Как передать `require_level_keyword` в фильтр: флаг в `Posting` или параметр фильтра по источнику, лишь бы для сайтов ничего не поменялось.

## Изменение

Правило уровня для источников с `require_level_keyword` теперь пропускает вакансию и при `Employment.INTERNSHIP` или опыте 0 (не только по слову уровня в названии). Этот флаг использует и Авито.
